Résumé d'une note de `Cours/Year 4/SHS`, dans [[SHS (matière)]]. Transcription d'un entretien entre deux étudiants pour l'enquête sur le [[Open design|design libre]], où l'enquêtée décrit sa pratique de l'open source.

- **Pratique.** Environ deux ans sur GitHub : sites web, applications (un projet d'application de taxi pour femmes, dont la maquette est publiée au fil de l'avancement), et des « briques » réutilisables comme des Lego. La moitié des dépôts est privée (confidentialité), l'autre publique.
- **Motivation.** D'abord l'hébergement, puis la communauté et le travail d'équipe. Elle se déclare contre les écosystèmes fermés et travaille avec Linux. Personne ne réutilise encore ses codes.
- **Pratiques de publication.** Publier dès le premier jour, puis faire un « grand nettoyage » (readme, arborescence, noms de variables) pour que le dépôt soit réutilisable, mais pas pour tous les projets. Conventions : le readme est fondamental, fichiers markdown et JSON, fichiers d'instructions pour agents de code.
- **Effet de l'IA.** Selon elle, beaucoup de dépôts récents sont produits avec un assistant de code qui apparaît comme co-auteur ; les projets bâclés ([[IA slop]]) noient les bons projets d'experts, sans gêner celui qui sait quoi chercher. Elle retire de ses dépôts toute mention de l'assistant.
- **Reconnaître un projet de qualité.** Un dépôt propre a un [[Fichier README]] et une arborescence claire, avec des noms de variables explicites ; c'est au développeur de donner les prérequis pour qu'on puisse réutiliser son travail. Trois critères pour juger un dépôt trouvé sur GitHub : il est mis à jour régulièrement (commits récents), une communauté y contribue, et il a beaucoup d'étoiles.
- **Diffusion.** Pour son activité rémunérée, uniquement le bouche-à-oreille auprès de petits clients ; aucune promotion sur les réseaux. Ses liens partagés en story n'ont pas été cliqués. Elle découvre elle-même les bons projets surtout par les réseaux sociaux à défilement (Twitter, réels Instagram), où une petite communauté de développeurs met en avant ses dépôts.
- **Règles de réutilisation.** Aucune licence pour l'instant : réutilisation entièrement libre, y compris commerciale. Elle exigerait peut-être une mention pour un usage commercial si ses projets devenaient connus. Elle sait qu'une licence se place en fin de README, et parfois des mentions de droits en tête (« CC… »), sans connaître la démarche : voir [[Licences libres]] et [[Creative Commons]].
- **Savoir qui réutilise.** GitHub notifie certains clonages, pas tous : on peut reprendre un code sans que l'auteur le sache. Une contribution passe en revanche par une [[Demande de fusion]] (*pull request*), que l'auteur accepte ou refuse.
- **Contribution.** Elle a proposé une demande de fusion à une bibliothèque Python de détection de gestes par caméra (un ajout visuel pour illustrer la bibliothèque) ; elle a été refusée.

Voir aussi [[Licences libres]] et [[Open design]]. Les propos sont ceux d'une interviewée : ce sont des observations personnelles, non des faits établis (par exemple « la majorité » des dépôts récents, ou le fonctionnement des notifications de GitHub).
