## Obtenir de l'aide sur une commande

Trois façons de voir le détail d'une commande : `man command` ([[Commande man]]), `command --help` ([[Option --help]]), `info command` ([[Commande info]]).

Le manuel est découpé en **sections** numérotées : 1 pour les commandes utilisateur, 5 pour les formats de fichiers, 8 pour les commandes d'administration, entre autres. Un même nom peut exister dans plusieurs sections : `man passwd` montre la commande, `man 5 passwd` le fichier `/etc/passwd`. Dans `man`, on cherche un mot avec `/mot`, on passe à l'occurrence suivante avec `n` et on quitte avec `q` ; `man -k mot` (ou `apropos mot`) cherche les pages qui parlent d'un sujet. ## sudo et mots de passe

**`sudo`** (*superuser do*, [[Commande sudo]]) : permet aux utilisateurs autorisés de lancer des commandes avec les privilèges du super-utilisateur ([[Super-utilisateur root]]), sans se connecter en root, tout en gardant la sécurité et le contrôle des accès.

« Utilisateur autorisé » signifie : cité dans le fichier `sudoers`, en général via un groupe (`sudo` sous Debian et Ubuntu, `wheel` sous Fedora ou Arch) ; on ajoute quelqu'un à ce groupe avec `sudo usermod -aG sudo nom`. `sudo` demande le mot de passe **de l'utilisateur**, pas celui de root, et garde la trace de chaque commande lancée (sous Ubuntu, dans `/var/log/auth.log`). Par défaut, `sudo` exécute en root ; `sudo -u autre commande` l'exécute sous un autre compte. [[Complément hors du cours|ⓘ]]

**sudo sans mot de passe** ([[Fichier sudoers]]) :
1. ouvrir le fichier `sudoers` : `sudo visudo` ;
2. ajouter en fin de fichier, en remplaçant `username` par le vrai nom d'utilisateur :

```
username ALL=(ALL) NOPASSWD:ALL
```

**sudo avec un délai avant la demande suivante** :
1. `sudo visudo` ;
2. ajouter ou modifier la valeur `timestamp_timeout`, par exemple pour un délai de 15 minutes (pas de nouvelle demande de mot de passe pendant 15 minutes après la première commande `sudo` réussie) : [[Erreurs du cours#^e-1-tp1|✎]]

```
Defaults timestamp_timeout=15
```

On passe par `visudo` plutôt que par un éditeur ordinaire parce qu'il vérifie la syntaxe avant d'enregistrer : une erreur dans `sudoers` peut rendre `sudo` inutilisable, et donc empêcher de corriger le fichier sans passer par root. Avec `timestamp_timeout`, la valeur `0` redemande le mot de passe à chaque commande et une valeur négative ne le redemande plus jusqu'au redémarrage. `NOPASSWD:ALL` est pratique sur une machine de TP, mais à éviter ailleurs : quiconque accède à la session obtient tous les droits sans rien taper. [[Complément hors du cours|ⓘ]]

**Changer le mot de passe** : `sudo passwd` ([[Commande passwd]]).

Attention à la cible : `passwd` seul change le mot de passe de l'utilisateur courant (il demande l'ancien) ; `sudo passwd nom` change celui de l'utilisateur `nom` sans demander l'ancien ; `sudo passwd` sans nom change le mot de passe **de root**, ce qui, sous Ubuntu où le compte root est verrouillé par défaut, revient à l'activer. [[Complément hors du cours|ⓘ]]

**Voir son mot de passe** : impossible, pour des raisons de sécurité et de confidentialité, sous Ubuntu et les autres systèmes de type Unix. Les mots de passe sont stockés sous forme hachée ([[Hachage de mot de passe]]) dans `/etc/shadow` ([[Fichiers de mots de passe]]) : ce fichier ne révèle pas le mot de passe lui-même, et seul un utilisateur ayant les droits root peut y accéder. Même un administrateur ne peut donc pas lire directement le mot de passe d'un utilisateur.

Un **hachage** est une fonction à sens unique : on calcule facilement l'empreinte d'un mot de passe, mais on ne peut pas remonter de l'empreinte au mot de passe. À la connexion, le système hache ce qui est tapé et compare les deux empreintes. Dans `/etc/shadow`, le champ du mot de passe a la forme `$id$sel$empreinte`, où `id` désigne l'algorithme (`6` pour SHA-512, `y` pour yescrypt, le défaut des Ubuntu récentes) et où le **sel** (*salt*) est une valeur aléatoire propre à chaque compte : deux utilisateurs qui ont le même mot de passe n'ont pas la même empreinte, ce qui empêche l'usage de tables précalculées. Un administrateur qui a perdu un mot de passe ne le retrouve pas : il le remplace avec `passwd`. [[Complément hors du cours|ⓘ]]

## Clavier et nom de la machine

**Changer la disposition du clavier** ([[Disposition du clavier]]) :
- **temporairement** (perdu au redémarrage) : `setxkbmap <layout>`, par exemple `setxkbmap us` ;
- **définitivement** : `sudo nano /etc/default/keyboard`, puis modifier la ligne `XKBLAYOUT` avec le code voulu (`XKBLAYOUT="us"` ou `XKBLAYOUT="fr"`).

`setxkbmap` ne vaut que pour une session graphique X11 ([[Wayland et X11]]) ; sous Wayland, la disposition se règle dans les paramètres de l'environnement de bureau. Sur les distributions avec `systemd`, `localectl set-keymap fr` (console) et `localectl set-x11-keymap fr` (session graphique) font le réglage définitif sans éditer le fichier à la main ; `localectl status` affiche la disposition en cours. [[Complément hors du cours|ⓘ]]

**Changer le nom de la machine** ([[Nom d'hôte]], [[Commande hostname]]) : `sudo hostname new_hostname`.

Ce changement n'est que **temporaire** : il est perdu au redémarrage, car le nom est relu au démarrage dans le fichier `/etc/hostname`. Pour un changement durable, `sudo hostnamectl set-hostname nouveau_nom` (sur les systèmes avec `systemd`) met à jour ce fichier ; il faut aussi remplacer l'ancien nom dans `/etc/hosts` ([[Fichier hosts]]), sinon `sudo` affiche un avertissement « unable to resolve host ». Le nom `penguin` qui apparaît dans les invites du TP est le nom par défaut du conteneur Linux de ChromeOS. [[Complément hors du cours|ⓘ]]

Rôle du nom d'hôte :
1. **Identification** : il identifie de façon unique un ordinateur ou un appareil sur le réseau ; chaque appareil doit avoir le sien pour éviter conflits et confusions.
2. **Adresse lisible** : plus facile à retenir qu'une adresse IP.
3. **Fonctions réseau** : adressage du courrier électronique, accès aux services du réseau.

Utilité en réseau :
1. **Résolution de noms** : le [[DNS]] traduit le nom d'hôte en adresse IP ; quand on tape un nom dans le navigateur, les serveurs DNS donnent l'adresse IP du serveur visé.
2. **Réseau local** : on atteint imprimantes, serveurs ou ordinateurs sans connaître leur adresse IP, par exemple `ssh user@hostname`.
3. **Identification des services** : les services web tournent souvent sur des serveurs aux noms précis, ce qui facilite la gestion des ressources.

## Créer des fichiers et des arborescences

**Plusieurs fichiers d'un coup** ([[Commande touch]], [[Expansion d'accolades]]) :

```
sudo touch test{1..3}.txt
```

C'est le **shell** qui développe les accolades avant de lancer la commande : `touch` reçoit en réalité `test1.txt test2.txt test3.txt`. `touch` crée un fichier vide s'il n'existe pas, et sinon ne fait que mettre à jour sa date de modification. Le `sudo` est inutile dans son propre répertoire, et même gênant : les fichiers créés appartiennent alors à root, et l'utilisateur ne peut plus les modifier sans `sudo`. [[Complément hors du cours|ⓘ]]

**Une arborescence de dossiers** : `mkdir -p` à la place de `touch` ([[Commande mkdir]]), vérifiée ensuite avec `tree` ([[Commande tree]]) :

```
mkdir -p semester/{first/{os,uc},second/{cn,db,ns,cs},third/{iot,sp,dc}}
```

![[1 - TP1 - image12.png]]
*Figure : la commande `mkdir -p` dans le terminal, puis `tree semester/` : 13 répertoires (first, second, third et leurs sous-dossiers), 0 fichier.*

L'option `-p` (*parents*) crée au passage les dossiers intermédiaires manquants (`semester`, puis `first`…) et ne signale pas d'erreur si un dossier existe déjà ; sans elle, `mkdir semester/first/os` échoue tant que `semester/first` n'existe pas. Les accolades imbriquées se développent elles aussi avant l'exécution : `semester/{first/{os,uc},…}` devient `semester/first/os semester/first/uc …`. Attention à ne pas mettre d'espace dans les accolades, sinon le shell ne les développe pas. [[Complément hors du cours|ⓘ]]

**Écrire du texte dans un fichier** ([[Commande echo]], [[Redirection et tube]]) :

```
touch semester/first/semester.txt && echo "first" | cat > semester/first/semester.txt
```

Cette ligne écrit « first » dans `semester.txt`.

Décomposition : `&&` n'exécute la seconde commande que si la première a réussi ; `|` envoie la sortie de `echo` à `cat`, et `>` redirige la sortie de `cat` vers le fichier. La forme courte `echo "first" > semester/first/semester.txt` fait la même chose : `>` crée le fichier s'il n'existe pas (le `touch` est donc facultatif) et **écrase** son contenu s'il existe, alors que `>>` **ajoute** à la fin. [[Complément hors du cours|ⓘ]]

**Changer les droits de tout un dossier** ([[Commande chmod]], [[Permissions Unix]]) : le `man chmod` indique que l'option `-R` (`--recursive`) change le mode des fichiers et dossiers récursivement. D'où :

```
sudo chmod -R 444 semester/
```

`444` donne `r--r--r--` : lecture seule pour le propriétaire, le groupe et les autres. Sur un **dossier**, les droits n'ont pas le même sens que sur un fichier : `r` permet de lister les noms qu'il contient, `w` d'y créer, renommer ou supprimer des fichiers, et `x` d'y entrer (`cd`) et d'accéder à ses fichiers. Après `chmod -R 444`, les dossiers n'ont plus de `x` : on ne peut plus entrer dans `semester/` ni lire les fichiers qu'il contient, même en lecture seule (sauf en root). Pour mettre les fichiers en lecture seule tout en gardant les dossiers accessibles, on utilise `chmod -R a-w semester/`, ou `555` sur les dossiers et `444` sur les fichiers. [[Complément hors du cours|ⓘ]]

## Réponses aux questions du TP

- **`whoami` et `hostname`** : `whoami` donne l'utilisateur connecté à la machine ([[Commande whoami]]) ; `hostname` donne le nom de la machine utilisée.
- **Déplacements** ([[Commande cd]]) :
  - `cd ..` remonte au dossier parent : depuis `/home/momo/test`, on arrive dans `/home/momo` ;
  - `cd ~` fait comme `cd` seul : il ramène au [[Répertoire personnel]] de l'utilisateur courant ;
  - `cd -` revient au dossier précédent : depuis `/home/momo`, après être passé dans `/etc/apt`, `cd -` ramène dans `/home/momo`.
- **`./`** désigne le dossier courant ([[Chemin de fichier]]).
  - Un chemin qui commence par `/` est **absolu** (il part de la [[Répertoire racine|racine]], comme `/etc/apt`) ; sinon il est **relatif** au dossier courant (`./script.sh`, `../test`). On écrit `./script.sh` pour lancer un script du dossier courant parce que le shell ne cherche les commandes que dans les dossiers listés par la variable `PATH`, qui ne contient pas le dossier courant, par sécurité. [[Complément hors du cours|ⓘ]]
- **Éteindre le système** : `sudo shutdown now` ou `sudo poweroff` ([[Commandes shutdown et poweroff]]).
  - `shutdown` accepte aussi un délai et prévient les utilisateurs connectés : `sudo shutdown +10` éteint dans 10 minutes, `sudo shutdown 22:00` à 22 h, `sudo shutdown -c` annule. `sudo shutdown -r now` ou `sudo reboot` redémarre. [[Complément hors du cours|ⓘ]]
- **Informations système** : la commande `uname` ([[Commande uname]]) ; d'après le manuel, l'option `-r` affiche la version du [[Noyau]] :

```
momo@penguin:~$ uname -r
6.6.30-02726-gb84bbdf6955e
```

Lecture du numéro : `6.6.30` signifie version majeure 6, mineure 6, correctif 30 ; la suite est propre à la compilation (ici le noyau fourni par ChromeOS). Autres options utiles : `uname -a` affiche tout (nom du noyau, nom d'hôte, version, architecture), `uname -m` l'architecture matérielle (`x86_64`, `aarch64`). Pour la distribution elle-même, et non le noyau, on lit `/etc/os-release` (`cat /etc/os-release`). [[Complément hors du cours|ⓘ]]

- **Mise à jour des paquets** ([[APT]]) : `apt upgrade` met à jour les paquets installés sans jamais en supprimer (il installe seulement les nouveaux paquets exigés par les dépendances) ; `apt full-upgrade` peut supprimer des paquets et en installer de nouveaux. [[Erreurs du cours#^e-1-tp1|✎]]
  - Ces deux commandes se lancent **après** `sudo apt update`, qui télécharge la liste à jour des paquets disponibles depuis les dépôts : sans elle, `upgrade` ne connaît pas les nouvelles versions. D'où l'enchaînement habituel `sudo apt update && sudo apt upgrade`. D'après `man apt-get`, c'est `apt-get upgrade` qui n'installe ni ne supprime aucun paquet : une mise à jour qui exigerait un nouveau paquet y est laissée de côté. `full-upgrade` sert quand une mise à jour impose de retirer des paquets devenus incompatibles. [[Complément hors du cours|ⓘ]]
