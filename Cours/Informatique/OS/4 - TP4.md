Résumé de [[Raw/Year 2/Operating System/Cours OS/Cours TP4.docx|Cours TP4]], dans [[Cours/Informatique/OS/_index|Operating System]]. Séance de TP en deux parties : un programme C à deux processus qui sauvegarde un fichier, puis la planification de tâches avec cron.

## Programme C à deux processus

*Consigne* : créer un programme C avec deux [[Processus|processus]] :
- le **parent** ajoute l'heure à un fichier toutes les 5 secondes ;
- le **fils** assure la [[Sauvegarde de fichier|sauvegarde]] de ce fichier en écrasant la sauvegarde précédente, toutes les 10 secondes.

Méthode :
1. `fork()` ([[Appel fork()]], [[Création et terminaison de processus]]) sépare les deux rôles selon le [[Identifiant de processus|pid]] renvoyé ;
2. le parent ouvre le fichier en mode ajout (`"a"`), y écrit `ctime(&current_time)`, le ferme, puis `sleep(5)` ;
3. le fils lance la commande shell `cp` grâce à `system()` ([[Fonction system() en C]]), puis `sleep(10)` ;
4. les deux tournent en boucle infinie `while(1)`.

`fork()` duplique le processus appelant : à son retour, deux processus exécutent la suite du même code, avec chacun sa propre copie des variables. La seule différence est la valeur renvoyée : **0 dans le fils**, le **PID du fils** (strictement positif) dans le parent, et **−1** dans le parent si la création a échoué (aucun fils n'existe alors). D'où le `if (pid == 0)` / `else if (pid > 0)` ; le cas `pid < 0` n'est pas traité ici. [[Complément hors du cours|ⓘ]]

```c
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <time.h>
#include <sys/wait.h>

void append_current_date(char *filename) {
    FILE *file = fopen(filename, "a");
    time_t current_time = time(NULL);
    fprintf(file, "%s", ctime(&current_time));
    fclose(file);}

void copy_file() {
    system("cp /home/momo/data/time.txt /home/momo/backup/time.txt");
}

int main() {
    pid_t pid = fork();
    int status;
    if(pid==0){                // fils : sauvegarde toutes les 10 s
        while(1){
            copy_file();
            sleep(10);}}
    else if(pid>0){            // parent : ajoute l'heure toutes les 5 s
        while(1){
            append_current_date("time.txt");
            sleep(5);
        } waitpid(pid, &status, 0);}
    return 0;}
```

Voir aussi [[Appels wait() et waitpid()]] et [[Structure conditionnelle]].

Points du programme à comprendre : [[Complément hors du cours|ⓘ]]
- **Chemin relatif et chemin absolu.** Le parent écrit dans `"time.txt"`, chemin relatif résolu à partir du répertoire de travail du processus (celui d'où l'on a lancé le programme), alors que le fils copie `/home/momo/data/time.txt`, chemin absolu. Les deux ne désignent le même fichier que si le programme est lancé depuis `/home/momo/data` ; sinon le fils sauvegarde un autre fichier, ou échoue. Utiliser le même chemin absolu des deux côtés évite le problème (voir [[Chemin de fichier]]). [[Complément hors du cours|ⓘ]]
- **`ctime()`** convertit un `time_t` (nombre de secondes depuis le 1er janvier 1970 à 0 h UTC, l'« epoch » Unix) en une chaîne lisible du type `Sun Nov  8 14:03:12 2026\n` (en heure locale), qui finit déjà par un saut de ligne : c'est pourquoi `fprintf(file, "%s", …)` produit une ligne par date. [[Complément hors du cours|ⓘ]]
- **Ouvrir et fermer à chaque tour.** Fermer le fichier après chaque écriture vide le tampon de `stdio` sur le disque ; sans `fclose` (ou `fflush`), le fils risquerait de copier un fichier où les dernières dates ne sont pas encore écrites. `fopen` renvoie `NULL` en cas d'échec (dossier inexistant, droits insuffisants), cas qu'un programme robuste teste avant `fprintf`. [[Complément hors du cours|ⓘ]]
- **`waitpid()` n'est jamais atteint.** Il est placé après une boucle `while(1)` sans `break` : le parent ne sort jamais de la boucle. Il servirait, si le parent s'arrêtait, à attendre la fin du fils et à récupérer son code de retour, pour éviter qu'il reste [[Processus zombie et orphelin|zombie]]. [[Complément hors du cours|ⓘ]]
- **Arrêter le programme.** Ctrl+C dans le terminal envoie le signal `SIGINT` à tous les processus du groupe au premier plan, donc au parent et au fils, qui s'arrêtent tous deux. Si l'on ne tue que le parent (`kill <pid>`, voir [[Commande kill]]), le fils devient [[Processus zombie et orphelin|orphelin]], est rattaché à `init` ([[Processus init]]) et continue ses sauvegardes : il faut le tuer à son tour (`ps -ef | grep` pour trouver son PID). [[Complément hors du cours|ⓘ]]
- **`system()`** lance un shell (`/bin/sh -c "…"`) qui lance à son tour `cp` : c'est simple, mais cela crée deux processus à chaque copie. La voie de plus bas niveau est `fork()` suivi d'un appel de la famille [[Appel exec()|exec()]] (par exemple `execlp("cp", "cp", src, dst, NULL)`), ou une copie faite en C avec `fread`/`fwrite`. [[Complément hors du cours|ⓘ]]

## Cron

[[Tâche planifiée cron|Cron]] est un [[Ordonnancement des processus|ordonnanceur]] de tâches fondé sur le temps, dans les [[Système d'exploitation|systèmes]] de type Unix dont [[Ubuntu]]. Il permet de programmer des tâches (*cron jobs*) qui s'exécutent automatiquement à intervalles donnés. On s'en sert pour automatiser des tâches répétitives : sauvegardes, maintenance, scripts. C'est un [[Démon (informatique)|démon]] géré par [[Commande systemctl|systemctl]].

### Commandes

```bash
sudo systemctl start cron     # démarrer cron
sudo systemctl enable cron    # le démarrer automatiquement au boot
sudo systemctl status cron    # voir si cron tourne
crontab -e                    # éditer la table des tâches
crontab -l                    # vérifier les tâches planifiées
crontab -r                    # supprimer toutes les tâches
```

Ne pas lancer `crontab -e` avec `sudo` : on éditerait la table du [[Super-utilisateur root|super-utilisateur root]] et non celle de l'utilisateur courant.

### Syntaxe d'une tâche

```
* * * * * /chemin/vers/la/commande
┬ ┬ ┬ ┬ ┬
│ │ │ │ │
│ │ │ │ └── Jour de la semaine (0 - 6) (Dimanche = 0)
│ │ │ └──── Mois (1 - 12)
│ │ └────── Jour du mois (1 - 31)
│ └──────── Heure (0 - 23)
└───────── Minute (0 - 59)
```

`*/15` signifie « toutes les 15 unités » du champ concerné.

Autres notations d'un champ : [[Complément hors du cours|ⓘ]]
- **liste** : `1,15` dans le champ du jour du mois = le 1er et le 15 ; [[Complément hors du cours|ⓘ]]
- **intervalle** : `1-5` dans le champ du jour de la semaine = du lundi au vendredi ; combinable avec un pas, `8-18/2` dans le champ des heures = 8 h, 10 h… 18 h ; [[Complément hors du cours|ⓘ]]
- le jour de la semaine accepte aussi `7` pour dimanche et les abréviations anglaises (`mon`, `fri`) ; [[Complément hors du cours|ⓘ]]
- si le jour du mois **et** le jour de la semaine sont tous deux restreints, la tâche s'exécute quand **l'un ou l'autre** correspond : `0 9 1 * 1` tourne le 1er du mois et chaque lundi ; [[Complément hors du cours|ⓘ]]
- raccourcis : `@reboot` (une fois au démarrage), `@hourly`, `@daily`, `@weekly`, `@monthly`, `@yearly` (équivalents de `0 * * * *`, `0 0 * * *`, etc.). [[Complément hors du cours|ⓘ]]

### Exemples

| Tâche | Ligne cron |
|---|---|
| Lancer un script toutes les minutes | `* * * * * /home/user/scripts/backup.sh` |
| Toutes les heures, à l'heure pile | `0 * * * * /home/user/scripts/backup.sh` |
| Toutes les 15 minutes | `*/15 * * * * /home/user/scripts/cleanup.sh` |
| Chaque lundi à 15 h | `0 15 * * 1 /home/user/scripts/weekly_report.sh` |
| À 22 h 30 le premier jour de chaque mois | `30 22 1 * * /home/user/scripts/monthly_report.sh` |
| Envoyer un mail chaque vendredi à 8 h | `0 8 * * 5 echo "Weekly report" \| mail -s "Report" user@example.com` |

Par défaut, cron ne permet pas de lancer une tâche toutes les X secondes : l'intervalle minimal est **1 minute**.

Pour descendre sous la minute, on garde un programme qui tourne en boucle avec `sleep` (comme le programme C ci-dessus), ou on utilise un *timer* de systemd, l'alternative moderne à cron sous les distributions qui utilisent systemd, qui accepte une précision à la seconde et journalise chaque exécution dans `journalctl`. [[Complément hors du cours|ⓘ]]

**Pièges classiques.** Une tâche cron ne s'exécute pas dans le terminal de l'utilisateur : son environnement est minimal (variable `PATH` réduite à `/usr/bin:/bin`, pas de répertoire courant choisi, pas de variables du `.bashrc`). D'où trois règles : écrire des **chemins absolus** pour les commandes et les fichiers, rendre un script exécutable (`chmod +x`, voir [[Permissions Unix]]), et rediriger la sortie pour garder une trace (`… >> /home/user/cron.log 2>&1`, voir [[Redirection et tube]]). Sous Ubuntu, les lancements de cron apparaissent dans `/var/log/syslog` ou avec `journalctl -u cron` ([[Commande journalctl]]). [[Complément hors du cours|ⓘ]]

À côté des crontabs des utilisateurs, il existe une crontab **système**, `/etc/crontab` (et les fichiers de `/etc/cron.d/`), dont les lignes ont un sixième champ avant la commande : le nom de l'utilisateur qui l'exécute. Les dossiers `/etc/cron.daily/`, `/etc/cron.weekly/`… contiennent des scripts lancés une fois par jour, par semaine… [[Complément hors du cours|ⓘ]]

### Créer une tâche

1. `crontab -e` ;
2. à la fin du fichier ouvert dans l'éditeur, ajouter la ligne de la tâche ;
3. sauvegarder et fermer : la tâche est planifiée.
