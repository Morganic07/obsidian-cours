## 1.1 Jokers (*Pattern matching or Wildcards*)

Servent à désigner des noms de fichiers ou des motifs de texte.

```bash
ls *.txt                # * : zéro caractère ou plus → tous les fichiers .txt
ls file?.txt            # ? : exactement un caractère → file1.txt, file4.txt…
ls file[123].txt        # [] : un caractère parmi ceux entre crochets → file1.txt, file2.txt, file3.txt
touch file{1,2,3}.txt   # {} : génère plusieurs options → crée file1.txt, file2.txt, file3.txt
```

Les accolades relèvent de l'[[Expansion d'accolades]].

C'est le shell, et non la commande, qui remplace le motif par la liste des noms correspondants avant de lancer la commande : `ls *.txt` reçoit déjà `file1.txt file2.txt …`. Si aucun fichier ne correspond, Bash laisse par défaut le motif tel quel (`ls` signale alors qu'il ne trouve pas `*.txt`). Les crochets acceptent aussi un intervalle (`file[1-5].txt`) et une négation (`file[!1].txt` : tout caractère sauf 1). À la différence des jokers, l'expansion d'accolades produit les noms même si les fichiers n'existent pas, d'où son usage avec `touch`. [[Complément hors du cours|ⓘ]]

## 1.2 Redirection

Redirige la sortie ou l'entrée d'une commande vers ou depuis un fichier ou une autre commande.

```bash
echo "Hello" > file.txt    # > : écrit dans le fichier, le crée ou l'écrase
echo "World" >> file.txt   # >> : ajoute à la fin du fichier
wc -l < file.txt           # < : prend l'entrée dans un fichier (compte les lignes)
ls | grep "file"           # | : tube, la sortie d'une commande devient l'entrée de la suivante
```

`wc -l` ([[Commande wc]]) compte seulement les lignes (`wc` signifie *word count*). [[Erreurs du cours#^e-2-tp2|✎]]

Chaque programme dispose de trois [[Flux standard|flux standard]], numérotés par des descripteurs de fichier : 0 l'entrée standard (*stdin*, le clavier par défaut), 1 la sortie standard (*stdout*, l'écran), 2 la sortie d'erreur (*stderr*, l'écran aussi). `>` et `>>` redirigent le flux 1 seulement ; les messages d'erreur se redirigent avec `2>` (`ls dossier_absent 2> erreurs.txt`), les deux flux ensemble avec `> fichier 2>&1`, et `2> /dev/null` les fait disparaître. Le tube `|` ne transmet lui aussi que la sortie standard. [[Complément hors du cours|ⓘ]]

Avec `wc -l < file.txt`, `wc` lit son entrée sans connaître le nom du fichier : il affiche seulement le nombre (`2`), alors que `wc -l file.txt` affiche le nombre suivi du nom (`2 file.txt`, comme sur la capture ci-dessous). [[Complément hors du cours|ⓘ]]

## 1.3 Tâches de fond (*Background and Job Control*)

Gérer l'ordre d'exécution ou lancer des tâches en arrière-plan.

- `&` : lance une commande en arrière-plan ;
- `;` : sépare plusieurs commandes exécutées l'une après l'autre.

Commandes de contrôle des tâches ([[Commande jobs]], [[Commandes fg et bg]]) :

| Commande | Rôle |
|---|---|
| `jobs` | voir les tâches en cours |
| `fg %1` | mettre la tâche [1] au premier plan |
| `bg %1` | mettre la tâche [1] en arrière-plan (comme `&`) |

Au lancement avec `&`, le shell affiche le numéro de tâche et le PID du processus (`[1] 4321`) et rend aussitôt l'invite. Pour passer au fond une commande déjà lancée au premier plan, on la suspend avec **Ctrl+Z** (elle est stoppée, pas terminée), puis `bg` la relance en arrière-plan ; **Ctrl+C** l'interrompt. `kill %1` termine la tâche 1. Une tâche de fond reste liée au terminal : elle s'arrête en général quand on le ferme, sauf si on l'a lancée avec `nohup`. [[Complément hors du cours|ⓘ]]

Outre `;`, qui enchaîne sans condition, le shell a deux séparateurs conditionnels, fondés sur le **code de retour** de la commande (0 en cas de succès, autre chose en cas d'échec, lisible dans `$?`) : `A && B` n'exécute `B` que si `A` a réussi, `A || B` seulement si `A` a échoué ([[Évaluation en court-circuit]]). C'est le `&&` de l'exemple `(cd folder && ls)` ci-dessous : si le dossier n'existe pas, `ls` n'est pas lancé. [[Complément hors du cours|ⓘ]]

## 1.4 Regroupement et guillemets (*Grouping and Quoting*)

Regrouper des commandes ou préserver la valeur littérale d'un texte.

```bash
(cd folder && ls)    # ( ) : groupe dans un sous-shell ; va dans folder, liste, puis revient
{ mkdir new_folder; cd new_folder; touch newfile.txt; }   # { } : groupe dans le shell courant
```

Voir [[Sous-shell]] et [[Guillemets en shell]].

La différence se voit après coup : le sous-shell `( )` est un processus enfant, donc son `cd` et ses variables disparaissent avec lui et l'on reste dans le dossier de départ ; avec `{ }`, le `cd new_folder` reste en vigueur une fois le groupe terminé. Syntaxe des accolades : un espace après `{` et un `;` (ou un retour à la ligne) avant `}` sont obligatoires. [[Complément hors du cours|ⓘ]]

- `' '` (apostrophes, *single quotes*) : préserve la valeur littérale de chaque caractère.
- `" "` (guillemets, *double quotes*) : préserve la plupart des caractères mais permet l'expansion des variables.

Exemples du support : [[Erreurs du cours#^e-2-tp2|✎]]

```bash
echo 'path $PWD'      # Outputs "path $PWD" (without expanding $PWD)
echo $PWD             # Outputs the path to the working directory. Note the output difference in the two commands.
echo 'Hello $USER'    # Outputs "Hello $USER" (without expanding $USER)
echo $USER            # outputs "<username>"
echo "Hello $USER"    # Outputs "Hello <username>"
echo "Path $PWD"      # Outputs "Path </path to the working directory>
```

![[Séance TP2 - image4.png]]
*Figure : `echo 'Hello $USER'` affiche `Hello $USER` ; `echo "Hello $USER"` affiche `Hello momo`.*

Entre guillemets doubles, restent actifs `$` (variables), les apostrophes inversées et `$( )` (substitution de commande) et `\` devant ces caractères ; les jokers et les espaces, eux, perdent leur sens spécial. D'où la règle pratique d'écrire `"$variable"` : si la valeur contient un espace, elle reste un seul argument au lieu d'être coupée en deux. [[Complément hors du cours|ⓘ]]

## 1.5 Caractères des chemins (*Special Characters for File Paths and Locations*)

Voir [[Chemin de fichier]] et [[Répertoire personnel]].

```bash
cd /home/user    # / : sépare les répertoires dans un chemin
cd ~             # ~ : répertoire personnel de l'utilisateur courant
./script.sh      # . : répertoire courant ; exécute script.sh qui s'y trouve
cd ..            # .. : répertoire parent ; remonte d'un niveau
```

Un chemin qui commence par `/` est **absolu** (il part de la racine) ; sinon il est **relatif** au répertoire courant (`cd ../docs`). Le `./` de `./script.sh` est nécessaire parce que le shell ne cherche les commandes que dans les dossiers listés par la variable `PATH`, qui ne contient pas le répertoire courant ; le script doit en outre avoir la permission d'exécution (`chmod +x script.sh`, voir [[Exécution d'un script]]). `cd -` revient au répertoire précédent. [[Complément hors du cours|ⓘ]]

## 1.6 Caractères d'échappement (*Special Escaping Characters*)

Traiter certains caractères comme des littéraux. [[Erreurs du cours#^e-2-tp2|✎]]

```bash
rm file\ name.txt     # \ : échappe le caractère suivant → supprime "file name.txt"
rm file\ file2.txt    # supprime le fichier nommé "file file2.txt" (l'espace échappé fait partie du nom)
echo `pwd`            # `` (backticks) : exécute la commande et substitue sa sortie → affiche le répertoire courant
```

Les apostrophes inversées (*backticks*) réalisent une [[Substitution de commande]]. Sur le clavier : Alt+7 (« Alt Gr + 7 » sur un clavier AZERTY). On s'en sert pour mettre le résultat d'une commande dans une variable ou un fichier.

La forme moderne de la substitution de commande est `$(commande)` : `echo $(pwd)` équivaut à ``echo `pwd` ``. Elle est préférée parce qu'elle se lit mieux et s'imbrique sans échappement (`$(basename $(pwd))`), ce que les apostrophes inversées ne permettent qu'en écrivant `` \` ``.
