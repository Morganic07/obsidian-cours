## a. Qu'est-ce qu'AWK ?

AWK est un outil de traitement de texte et un langage de programmation disponible sous [[Linux]] / Unix. Il sert à manipuler, chercher et analyser des fichiers texte structurés en lignes et en colonnes.

Son nom vient des initiales de ses trois auteurs, Aho, Weinberger et Kernighan, qui l'ont créé aux Bell Labs en 1977 ; la version installée sous Linux est souvent `gawk` (GNU awk) ou `mawk`. [[Complément hors du cours|ⓘ]]

**Structure d'un programme AWK.** Un programme est une suite de règles `motif { action }`. AWK lit l'entrée ligne par ligne (chaque ligne est un *enregistrement*), la découpe en champs `$1`, `$2`, …, puis, pour chaque règle dont le motif est vrai sur cette ligne, exécute l'action. Sans motif, l'action s'applique à toutes les lignes (`{print $2}`) ; sans action, la ligne est affichée (`awk 'NR==2' food.txt` équivaut à `awk 'NR==2 {print $0}' food.txt`). Le programme s'écrit entre apostrophes `'…'` pour que le shell n'interprète pas les `$` ([[Guillemets en shell]]). [[Complément hors du cours|ⓘ]]

AWK se range avec deux autres outils classiques du texte sous Unix : [[Commande grep|grep]] sélectionne les lignes qui contiennent un motif, `sed` transforme le texte (substitutions, suppressions de lignes), AWK raisonne par colonnes et sait calculer (sommes, moyennes, comptages). [[Complément hors du cours|ⓘ]]

Exemple avec un fichier texte :

![[Séance TP5 - image2.png]]
*Figure : `cat food.txt` : steak 2.50, lettuce 1.00, bun 1.50, tomato 0.90.*

```bash
awk '{print $2}' food.txt
```

affiche la deuxième colonne (`$2`), les prix. Pas de séparateur précisé : par défaut, c'est l'espace.

Plus précisément, le séparateur par défaut est « une suite d'espaces ou de tabulations » : plusieurs espaces consécutifs comptent comme un seul séparateur, et les blancs en début de ligne sont ignorés. Avec tout autre séparateur (`-F,`), deux virgules consécutives délimitent au contraire un champ vide. [[Complément hors du cours|ⓘ]]

![[Séance TP5 - image6.png]]
*Figure : sortie : 2.50, 1.00, 1.50, 0.90.*

Avec un [[Fichier CSV]] :

![[Séance TP5 - image19.png]]
*Figure : `cat food.csv` : bread,1.00 ; pasta,1.20 ; sauce,1.90 ; cheese,2.30.*

```bash
awk -F, '{print $1,$2}' food.csv
```

affiche les colonnes 1 et 2 en précisant le séparateur virgule avec l'option `-F,`.

![[Séance TP5 - image5.png]]
*Figure : sortie : bread 1.00, pasta 1.20, sauce 1.90, cheese 2.30 (séparées par un espace).*

## b. Les séparateurs

*Question* : quels séparateurs (*delimiters*) sépare les données d'un fichier ? Donner au moins quatre exemples.

*Réponse* ([[Séparateur de champs]]) : l'espace (fichiers `.txt`), la tabulation (fichiers `.tsv`, voir [[Fichier TSV]]), la virgule (`.csv`), le point-virgule (`.txt` ou `.csv`) ; on peut aussi citer les deux-points et la barre verticale (*pipe*).

Les deux-points séparent par exemple les champs de `/etc/passwd` : `awk -F: '{print $1}' /etc/passwd` liste les comptes du système ([[Fichiers de mots de passe]]). Pour un fichier TSV, la tabulation s'écrit `-F'\t'`. Le séparateur peut aussi être une [[Expression régulière]] : `-F'[,;]'` coupe sur la virgule **ou** le point-virgule. [[Complément hors du cours|ⓘ]]

## c. Les variables intégrées d'AWK

*Question* : quelles sont les principales variables intégrées (*built-in variables*) d'AWK ? Les expliquer avec exemples et commandes. Voir [[Variables intégrées d'AWK]].

| Variable | Sens |
|---|---|
| `FNR` | numéro de ligne dans le fichier en cours ; repart à zéro à chaque nouveau fichier |
| `NR` | numéro de la ligne courante dans l'ensemble des données ; s'incrémente à chaque ligne, même sur plusieurs fichiers |
| `NF` | nombre de champs (colonnes) de la ligne courante |
| `FS` | séparateur des données en entrée ; par défaut l'espace |
| `OFS` | séparateur utilisé par AWK pour afficher |
| `$0` | la ligne complète |

Trois autres variables servent souvent : `$NF`, le **dernier** champ de la ligne (`NF` vaut le nombre de champs, donc `$NF` est le champ numéro `NF`) ; `ORS`, le séparateur de sortie entre deux lignes (par défaut le saut de ligne) ; `FILENAME`, le nom du fichier en cours de lecture. Avec plusieurs fichiers, le motif `FNR==1` repère la première ligne de chacun, et `NR==FNR` n'est vrai que pendant la lecture du premier. [[Complément hors du cours|ⓘ]]

**FNR** :

```bash
awk '{print FNR}' food.txt food.csv
```

![[Séance TP5 - image9.png]]
*Figure : 1, 2, 3, 4 puis de nouveau 1, 2, 3, 4 : la numérotation repart pour le second fichier.*

**NR** :

```bash
awk '{print NR}' food.txt food.csv
```

![[Séance TP5 - image26.png]]
*Figure : 1 à 8 : la numérotation continue d'un fichier à l'autre.*

**NF**, sur un fichier dont les lignes n'ont pas le même nombre de colonnes :

![[Séance TP5 - image25.png]]
*Figure : `cat food2.txt` : « bread complete 1.20 », « sauce tomato 1.30 », « cereals 1.20 », « water ».*

```bash
awk '{print NF}' food2.txt
```

![[Séance TP5 - image8.png]]
*Figure : 3, 3, 2, 1 champs.*

**FS** : dans `food.csv` les données sont séparées par des virgules ; il faut l'indiquer à AWK. Deux écritures équivalentes :

```bash
awk 'BEGIN {FS=","} {print $1, $2}' food.csv
awk -F, '{print $1, $2}' food.csv     # plus rapide
```

![[Séance TP5 - image16.png]]
*Figure : les deux commandes donnent la même sortie (bread 1.00 … cheese 2.30).*

Le `BEGIN` n'est pas décoratif : `FS` doit être fixé avant la lecture de la première ligne. Écrit `awk '{FS=","} {print $1, $2}'`, le changement ne vaudrait qu'à partir de la deuxième ligne, la première ayant déjà été découpée avec l'espace ([[Blocs BEGIN et END d'AWK]]). [[Complément hors du cours|ⓘ]]

**OFS** : afficher les données séparées par `/` au lieu d'un espace.

```bash
awk -F, '{OFS="/"} {print $1, $2}' food.csv
```

![[Séance TP5 - image23.png]]
*Figure : bread/1.00, pasta/1.20, sauce/1.90, cheese/2.30.*

`OFS` ne s'insère qu'entre les arguments séparés par une **virgule** dans `print` : `print $1, $2` donne `bread/1.00`, alors que `print $1 $2` colle les deux champs (`bread1.00`), car deux valeurs juxtaposées sont concaténées. Ici `{OFS="/"}` est réexécuté à chaque ligne ; on l'écrit plus proprement une seule fois, `BEGIN {OFS="/"}`. [[Complément hors du cours|ⓘ]]

Pour une mise en forme précise (colonnes alignées, nombre de décimales), AWK a `printf`, avec les mêmes formats qu'en C ([[Fonctions printf et scanf]]) : `awk -F, '{printf "%-8s %5.2f\n", $1, $2}' food.csv` aligne les noms à gauche sur 8 caractères et les prix sur 5 caractères avec 2 décimales. Contrairement à `print`, `printf` n'ajoute pas de saut de ligne : il faut écrire `\n`. [[Complément hors du cours|ⓘ]]

**$0** : afficher la 2e ligne complète en combinant `NR` et `$0`.

```bash
awk 'NR==2 {print $0}' food.txt
```

![[Séance TP5 - image3.png]]
*Figure : `food.txt` (salami 4.0 ; Carrot rapee cru Leclerc 1.20 ; steak 2.50), puis la 2e ligne seule : « Carrot rapee cru Leclerc 1.20 ».*

## e. Compter les enregistrements de même puissance

```bash
awk -F'\t' '{count[$4]++} END {for (power in count) print power, count[power]}' car.tsv
```

- `count[$4]++` lit la 4e colonne (puissance) et incrémente un compteur par valeur (tableau associatif).
- Une fois le fichier lu, le bloc `END` s'exécute ([[Blocs BEGIN et END d'AWK]]).
- La [[Boucle (programmation)|boucle for]] parcourt chaque valeur distincte (variable `power`) et affiche la valeur avec son nombre (`count[power]`).

![[Séance TP5 - image22.png]]
*Figure : 100 → 2, 335 → 1, 160 → 1, 120 → 2, 165 → 2, 130 → 1, 249 → 1 (ordre non trié).*

**Pourquoi ça marche.** Un tableau AWK est un [[Tableau associatif|tableau associatif]] : ses indices ne sont pas des positions 0, 1, 2… mais des valeurs quelconques, ici les puissances (`count["165"]`). Une case qui n'existe pas encore vaut 0 (ou la chaîne vide) à sa première lecture, d'où `count[$4]++` sans initialisation. Les éléments sont rangés par hachage, et `for (power in count)` les parcourt dans un ordre **non spécifié** : c'est pourquoi la sortie n'est pas triée. [[Complément hors du cours|ⓘ]]

Pour obtenir une sortie triée, on envoie le résultat dans [[Commande sort|sort]] par un [[Redirection et tube|tube]] : `awk -F'\t' '{count[$4]++} END {for (p in count) print p, count[p]}' car.tsv | sort -n`. Le même comptage s'obtient sans AWK : `cut -f4 car.tsv | sort | uniq -c` ([[Commande uniq]]). [[Complément hors du cours|ⓘ]]

## g. Opérations de la section 1.6 sur `car.tsv`

**Filtrer sur la valeur d'une colonne** : voitures de puissance > 150.

```bash
awk -F'\t' '$4>150 {print $0}' car.tsv
```

`$4 > 150` ne garde que les lignes dont la 4e colonne dépasse 150 ; `{print $0}` les affiche en entier.

AWK n'a pas de types déclarés : un champ qui ressemble à un nombre est comparé **numériquement** à un nombre (`$4 > 150`), sinon la comparaison se fait sur les chaînes, dans l'ordre alphabétique (`"9" > "10"` est vrai entre chaînes). [[Complément hors du cours|ⓘ]]

**Calculer sur une colonne** : AWK sert aussi à agréger. La puissance moyenne : [[Complément hors du cours|ⓘ]]

```bash
awk -F'\t' '{total += $4} END {print "Moyenne :", total/NR}' car.tsv
```

`total` vaut 0 au départ, chaque ligne y ajoute sa puissance, et `END` divise par `NR`, le nombre de lignes lues ; ici $(165+100+130+120+100+160+335+249+120+165)/10 = 1644/10 = 164{,}4$. Le maximum se trouve de même : `$4 > max {max = $4} END {print max}`. [[Complément hors du cours|ⓘ]]

![[Séance TP5 - image15.png]]
*Figure : résultat : 1 Peugeot 308 165 ; 6 Ford Focus 160 ; 7 BMW X5 335 ; 8 Audi Q5 249 ; 10 Peugeot 5008 165.*

**Chercher une chaîne (sensible à la casse)** : toutes les Peugeot.

```bash
awk -F'\t' '/Peugeot/ {print $0}' car.tsv
```

![[Séance TP5 - image12.png]]
*Figure : 1 Peugeot 308 165 ; 3 Peugeot 208 130 ; 10 Peugeot 5008 165.*

`/Peugeot/` seul est un raccourci de `$0 ~ /Peugeot/` : le motif est cherché **dans toute la ligne**, quelle que soit la colonne. Pour ne tester que la colonne du constructeur, on écrit `$2 ~ /Peugeot/` ; `$2 == "Peugeot"` exige en plus que le champ soit exactement ce mot. [[Complément hors du cours|ⓘ]]

**Recherche insensible à la casse** : si le fichier contenait des noms en majuscules et en minuscules, on convertit chaque ligne en minuscules avec `tolower` ([[Fonctions intégrées d'AWK]]) avant de comparer.

```bash
awk -F'\t' 'tolower($0) ~ /peugeot/ {print $0}' car.tsv
```

![[Séance TP5 - image11.png]]
*Figure : même résultat que la recherche sensible à la casse (trois Peugeot).*

## h. En-tête et message de fin avec `BEGIN` et `END`

*Consigne* : afficher ID, constructeur et puissance ; en tête, la phrase *« The list of manufacturers and the car powers they produced »* ; à la fin, *« The file is finished. »* ; utiliser `BEGIN` et `END` (section 1.7). Réponse : [[Erreurs du cours#^e-5-tp5|✎]]

```bash
awk -F'\t' 'BEGIN {print "The list of manufacturers and the car powers they produced"} {print $1, $2, $4} END {print "The file is finished."}' car.tsv
```

`BEGIN` affiche l'en-tête avant la lecture du fichier, `print $1, $2, $4` affiche l'ID, le constructeur et la puissance de chaque ligne, `END` affiche le message final. [[Erreurs du cours#^e-5-tp5|✎]]

![[Séance TP5 - image1.png]]
*Figure : l'en-tête, les dix lignes de `car.tsv`, puis « The file is finished. ».*

## Recherche par motif dans une chaîne (*pattern-based search*)

Fichier `log.txt` : journal de connexions (voir [[Fichier journal]]).

| Timestamp | Username | Login Time | Logout Time | Duration | Web Activity |
|---|---|---|---|---|---|
| 2024-10-31 08:00:00 | alice | 2024-10-31 08:00 | 2024-10-31 10:15 | 2h 15m | youtube.com, technews.com |
| 2024-10-31 09:30:00 | bob | 2024-10-31 09:30 | 2024-10-31 11:00 | 1h 30m | opensource.org, linux.org |
| 2024-10-31 10:00:00 | charlie | 2024-10-31 10:00 | 2024-10-31 10:30 | 2h 30m | youtube.com, facebook.com |
| 2024-10-31 11:45:00 | diana | 2024-10-31 11:45 | 2024-10-31 10:45 | 1h 00m | researchgate.net, youtube.com |
| 2024-10-31 10:30:00 | edward | 2024-10-31 10:30 | 2024-10-31 14:00 | 1h 30m | github.com, docs.python.org |

*Objectif* : trouver les utilisateurs qui ont consulté youtube.com et facebook.com.

Raisonnement :
1. dans `log.txt`, le séparateur des champs est la barre verticale `|` ;
2. la colonne utile est la 6e (*Web Activity*) ;
3. le texte est en minuscules : pas besoin de recherche insensible à la casse ;
4. la forme de la question f (`$3=="Golf"`) ne marche pas ici : les sites sont séparés par des virgules dans un même champ, et `==` exige une correspondance littérale du champ entier ;
5. pour chercher un motif **à l'intérieur** d'une chaîne, on utilise l'opérateur `~` et on met le motif entre deux `/` ([[Expression régulière]]).

```bash
awk -F"|" '$6~/youtube/ || $6~/facebook/ {print $2}' log.txt
```

`||` signifie « OU » ; pour les utilisateurs ayant consulté YouTube **et** Facebook, on écrirait `&&` ([[Opérateur logique]]).

Les deux tests peuvent se fondre en une seule [[Expression régulière]], où `|` signifie « ou » : `$6 ~ /youtube|facebook/`. Si le fichier entoure les barres d'espaces (`| alice |`), ces blancs restent dans les champs (`" alice "`) : une raison de plus de préférer `~` à `==`, qui échouerait sur eux.
